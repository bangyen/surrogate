# Explainable Chess Engine

A chess engine that explains its moves in named features and centipawns — and
measures how faithful those explanations actually are.

[![CI](https://github.com/bangyen/surrogate/actions/workflows/ci.yml/badge.svg)](https://github.com/bangyen/surrogate/actions/workflows/ci.yml)
[![License](https://img.shields.io/github/license/bangyen/surrogate)](LICENSE)

**[▶ Play it in your browser](https://bangyen.github.io/surrogate/demo.html)** — the
engine is compiled to WebAssembly and runs entirely in the page. No install, no
server, no Stockfish.

Most engines give you a number. This one names the features behind it, and then
holds itself to account: a surrogate model is audited against the engine's own
preferences, and the numbers below are regenerated by `just metrics` rather than
asserted.

| Metric | Value | Target | |
|--------|-------|--------|---|
| Decisive Faithfulness | **0.877 ± 0.080** | ≥ 0.80 | ✅ |
| Explanation Sparsity | **4.489** | ≤ 5.00 | ✅ |
| Position Coverage | **1.000** | ≥ 0.70 | ✅ |
| Move Ranking (τ) | **0.257** | ≥ 0.15 | ✅ |
| Fidelity (delta-R²) | **0.536** | ≥ 0.40 | ✅ |

Every metric is a CI gate: a change that degrades explanation quality fails the
build. [Full results and methodology ↓](#results)

### What is in here

- A native alpha-beta search — transposition table, killers, history, null-move,
  SEE, Zobrist hashing — with no dependency on an external engine.
- A linear surrogate model over 60 positional features, trained against
  Stockfish, whose per-feature contributions *are* the explanation.
- An audit harness implementing faithfulness, sparsity, coverage, move-ranking
  and fidelity metrics, seeded so runs are reproducible.
- King of the Hill, Three-Check and Antichess, sharing the same search.
- The whole pure core compiled to WebAssembly for the browser demo.

## Quickstart

### Prerequisites

- [Rust 1.75+](https://rustup.rs/)
- [Just](https://github.com/casey/just) (optional, but recommended)
- [Stockfish Engine](https://stockfishchess.org/) (installed and in PATH, or set `STOCKFISH_PATH`)

### Installation

```bash
git clone https://github.com/bangyen/surrogate.git
cd chess
just build
```

A pretrained `model.json` is checked in, so the explanation commands work on
a fresh clone. Retrain it whenever the features or trainer change:

```bash
just train --n-positions 200
```

### Usage Options

**CLI Tools:**
```bash
# Measure explainability metrics and write audit-results.json
just metrics

# Verify a committed report still meets its targets
just metrics-check

# Inspect features and explanations for the starting position
just audit

# ...or on a specific position
just audit --fen "r1bqkbnr/pppp1ppp/2n5/4p3/2B1P3/5N2/PPPP1PPP/RNBQK2R b KQkq - 0 1"

# Play interactive chess with explanations
just play

# Play a variant against the native engine (no Stockfish needed)
just variant koth
just variant antichess
```

**Web Interface:**
```bash
# Launch the Axum-based web dashboard (needs Stockfish)
just web
# Then open http://localhost:5000

# ...or build the browser demo, which needs nothing but a browser
just wasm
just demo
```

The browser demo compiles the engine, feature extraction and ML inference
to WebAssembly and runs them in the page — no server, no Stockfish. The
opponent is this project's own alpha-beta search, and the surrogate model
ships as a JSON asset, so explanations work offline. It deploys to GitHub
Pages on every push to `main`.

## Results
<a id="results"></a>

Measured by `just metrics` at depth 12 against a surrogate trained on 400
positions. Sampling is seeded, so runs are reproducible: `just metrics`
regenerates this table and `just metrics-check` verifies the committed report
in CI.

| Metric | Value | Target | | n |
|--------|-------|--------|---|---|
| Decisive Faithfulness | **0.877 ± 0.080** | ≥ 0.80 | ✅ | 65 |
| Explanation Sparsity | **4.489** | ≤ 5.00 | ✅ | 92 |
| Position Coverage | **1.000** | ≥ 0.70 | ✅ | 92 |
| Move Ranking (tau) | **0.257** | ≥ 0.15 | ✅ | 297 |
| Fidelity (delta-R2) | **0.536** | ≥ 0.40 | ✅ | 888 |

Measured over 297 of 300 sampled positions at depth 12 (seed `1592640741`).

**What the surrogate does.** It models the *difference between the candidate
moves available from one position* — which is what an explanation is actually
for. Ask it "why this move rather than that one" and it answers with a handful
of named features and their centipawn weights.

**Targets are regression guards, not aspirations.** Each sits below the
measured baseline with margin for sampling noise, so a failure means something
broke rather than that the approach fell short of an ideal. Faithfulness is
computed only over positions where the engine had a clear preference, so its
95% interval is roughly ±0.10 even at this sample size; the targets are set
where measurement can support them.

### What made the difference

An earlier version of this model scored τ ≈ 0.00 and fidelity ≈ 0.02, and this
README documented that as the ceiling of a linear surrogate over static
features. **That was wrong.** The ceiling was an artifact of what the model
was fit to.

Decomposing the training target by position shows that only ~26% of its
variance lies *within* a position; the rest is the difference *between*
positions. But move ranking and faithfulness are both within-position
measures — they compare candidate moves against each other. Fitting absolute
evaluation levels spent roughly three quarters of the model's capacity on an
axis those metrics ignore.

Centering the target and features per position before fitting removes that
axis. Same features, same linear model, same per-feature attribution — a
difference of linear models is still linear — but measured on identical
positions:

| | Level-fit | Centered |
|---|---|---|
| Decisive Faithfulness | 0.839 | **0.935** |
| Move Ranking (τ) | −0.023 | **0.279** |
| Fidelity | ≈ 0 | **0.575** (delta-R²) |

Feature correlations tell the same story: `material_diff` correlates 0.234
with the target on levels, and **0.629** within-position.

Fidelity is reported as delta-R² because a centered model does not predict
absolute levels — scoring it on levels would measure something it never
claimed to model. Delta-R² centers each position before comparing, the same
transformation the trainer applies, and answers the question that matters:
*how much of the difference between candidate moves does the surrogate
explain?*

An earlier table reported 86.7% faithfulness and R² 0.48, inherited from a
Python predecessor whose measurement code did not survive the Rust rewrite.
Those numbers described a gradient-boosted model over an enriched featureset
scored on a held-out split of its own training sample, and are not comparable
to anything above.

## Chess Variants

The search and move generation are shared with standard chess — every variant
implements the same position trait, so the alpha-beta search works unchanged.
What differs is *evaluation*: each variant wins differently, and reusing the
standard piece-square tables would produce legal but pointless play.

| Variant | Win condition | Evaluation |
|---------|---------------|------------|
| `koth` | March your king to a centre square | Standard eval plus a steep centre-proximity gradient |
| `3check` | Give check three times | Standard eval plus a term for checks remaining |
| `antichess` | Lose all your pieces; captures forced | Material inverted — pieces are a liability |

```bash
just variant --list      # show supported variants
just variant koth        # play King of the Hill
```

Atomic, Crazyhouse, Horde and Racing Kings are deliberately not offered: the
move generator supports them, but this engine has no evaluation for them and
would play legally while understanding nothing.

**Scope:** variants are engine-only. The ML explanation pipeline trains
against Stockfish, which plays standard chess exclusively, and the extracted
features encode standard-chess judgment. Explanations are therefore available
for standard chess alone.
